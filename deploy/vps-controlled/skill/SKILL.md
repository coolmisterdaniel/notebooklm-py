# NotebookLM на VPS

Пакет уже установлен из проверенного личного форка. Используй `notebooklm` из
`/root/.local/bin/notebooklm` или сервер MCP `notebooklm`. Процесс работает
от Linux-пользователя notebooklm. Локальная инструкция: `/opt/notebooklm/Инструкция.md`.
Зафиксированная версия и SHA: `/opt/notebooklm/installation.json`.

- Не устанавливай пакет повторно, не запускай uvx, pip upgrade или git pull.
  Любое обновление требует проверки изменений и подтверждения владельца.
- Для Google-входа, получения или переноса Master Token требуется отдельное
  разрешение. Первоначальная установка сама по себе его не даёт.
  Авторизация ещё не выполнена. Секреты не читать и не показывать агенту.
- После разрешённого входа проверь `notebooklm auth check --test --json`.
  Нужны status=ok и checks.token_fetch=true; эта проверка может обновить cookies.
  `notebooklm status` проверяет выбранный контекст, а не реальную авторизацию.
- У MCP `server_info(include_account=false)` — локальная диагностика;
  `include_account=true` может обращаться к Google. Содержимое авторизации не возвращать.
- Для CLI сначала уточняй синтаксис через `--help`; предпочитай `--json` и полные
  идентификаторы. Для команд по блокноту передавай `-n <идентификатор>`, не полагайся
  на общий выбранный контекст. После добавления источника дождись `source wait`.
- Разрешённый каталог загрузки файлов MCP: `/var/lib/notebooklm/uploads`.
  Он отделён от авторизации; не копируй туда файлы с секретами.
- Удаление, публикация, расширение доступа и работа с токенами требуют явного
  поручения. Генерация материалов и создание тестовых блокнотов допустимы
  в границах текущего разрешения владельца.
- Автоматическое восстановление cookies из действующего Master Token поддерживается
  установленным дополнением headless. При отзыве токена прекрати повторы и запроси
  разрешение на новый вход. Не передавай токен аргументом команды или текстом в чат.
