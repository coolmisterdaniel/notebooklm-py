# NotebookLM на VPS

## Что установлено

CLI, Python API и MCP из личного форка; дополнения mcp и headless.
Python 3.12.3; отдельный пользователь notebooklm без интерактивного входа.
Приложение и окружение принадлежат root и недоступны процессу для изменения.
Авторизация находится отдельно, в /root/vault-secrets/notebooklm (0700).
При запуске приватное пространство монтирования отображает только этот каталог
как /var/lib/notebooklm/auth; права /root не расширяются. После подготовки
процесс теряет права root. Запуск выполняется из терминала владельца VPS.

CLI: `notebooklm --version`, справка: `notebooklm --help`.
Команды запуска доступны владельцу VPS; локальный MCP запускается Codex по запросу
через `/opt/notebooklm/notebooklm-launch mcp` и не открывает сетевой порт.
В терминале Codex команда `/mcp` показывает подключённые серверы; после установки
нужна новая сессия Codex, чтобы в ней появились инструменты NotebookLM.
Навык: `$notebooklm-vps`.

После отдельного разрешения на Google-вход:

```sh
notebooklm auth check --test --json
notebooklm list --json
notebooklm create "Проверка установки" --json
notebooklm source add --help
notebooklm ask --help
notebooklm generate --help
```

Первая команда проверяет реальную сессию, вторая получает список блокнотов,
третья создаёт тестовый блокнот. Остальные показывают точный синтаксис версии.
Перед этими действиями требуется разрешённая и завершённая авторизация.
Для работы с источниками и вопросами используй конкретный возвращённый ID
блокнота с `-n`; после добавления источника дождись его готовности.
Автоматизации запускай через тот же wrapper: он выбирает правильные права,
окружение и каталог авторизации. Обычные shell-переменные намеренно не наследуются.

## Авторизация и восстановление

Google-авторизация пока не выполнена. Для Master Token нужен отдельный Google-аккаунт:
этот токен предоставляет широкий, долговременный доступ к аккаунту.

После отдельного разрешения первичный вход выполняется на доверенном компьютере
с браузером с использованием той же проверенной версии форка и дополнения browser.
Токен создаётся библиотекой из браузерного входа; пароль агенту передавать не нужно.
Обходить защитные проверки Google не следует. Альтернатива — обычная сессия cookies
без долговременного токена, но она требует повторного входа после истечения.

Перенос делается по SSH/SFTP без вставки содержимого в чат, отчёт, историю команд
или Git. Итоговый файл на VPS:
`/root/vault-secrets/notebooklm/profiles/default/master_token.json`,
владелец notebooklm:notebooklm, права 0600; каталог профиля 0700.
В этой установке файл не создан, не получен и не перенесён.
Не передавай Master Token через `--oauth-token` или другой аргумент командной строки.

После отдельного разрешения `notebooklm auth refresh` создаёт/обновляет сессию
из уже безопасно установленного токена. Cookies сохраняются в соседнем
`storage_state.json` с правами 0600. На перезапуске программа читает этот профиль;
действующий Master Token может восстановить истёкшие cookies без браузера.
Восстановление невозможно после отзыва Master Token: нужен новый разрешённый вход.
При утечке отзови связанное устройство/сессию через настройки безопасности Google;
не полагайся только на смену пароля. После отзыва останови использующие профиль
процессы. Удаление файлов производится отдельно по явному поручению владельца.

## Безопасное обновление

1. Проверить новые исходные коммиты и изменения зависимостей, авторизации,
   сетевых адресов, файловых операций, команд и сборки.
2. Подготовить отдельную ветку форка с точным SHA и новыми файлами фиксации версий.
   Проверить рабочий и сборочный наборы через OSV/pip-audit; скачать готовые колёса
   и сверить SHA-256. Не использовать изменяемые ветки при установке.
3. Собрать и проверить кандидата от непривилегированного пользователя, вне сети
   для локальных тестов. Сравнить зависимости и представить владельцу изменения.
4. Получить подтверждение владельца. Только после этого перенести новые исходные
   изменения в используемую ветку форка и установить проверенный набор.
5. Установить новую версию в отдельное окружение, проверить CLI и MCP, затем
   переключить только запуск NotebookLM. Сохранить возможность возврата к прошлому
   окружению. Не менять остальные MCP и настройки Codex.

На VPS нет задания cron, таймера systemd или сервиса обновления NotebookLM.
GitHub Actions форка отключены. При запуске программа ничего не устанавливает.
Сборка зафиксирована `build.lock`, рабочие зависимости — `runtime.lock` с хешами;
пакеты сохранены в `/opt/notebooklm/wheelhouse`, приложение — в `/opt/notebooklm/dist`.
Для повторной установки на совместимой Linux x86_64 / Python 3.12 используются
только эти артефакты и режимы --offline / --no-index / --require-hashes.
Системный Python и системные библиотеки управляются ОС и не заморожены этим набором.
